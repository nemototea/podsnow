# docs/ux-restructure.md — PodsNow 機能と導線の再設計（提案）

> 凡例: **【事実】** 対話で決定した仕様、またはこのリポジトリのコードを読んで確認した現状 / **【確認済み】** 公式ドキュメント等で確認済み（出典付き） / **【仮説】** 未検証・要スパイク

## 0. この文書の位置づけ

PodsNow を「自分用の収録アプリ」から「世界中の個人ポッドキャスターが最初に開く収録アプリ」へ引き上げるための、**機能と導線の再設計案**。

- 対象: 情報設計（IA）、収録前の準備、収録中の参照、編集操作、制作状況の見せ方、素材の扱い。
- この文書は **提案**。採用が決まった項目は `PRODUCT.md` / `REQUIREMENTS.md` / `DATA_MODEL.md` へ反映し、この文書は決定の経緯として残す（AGENTS.md「文書と実装が矛盾したら、コードではなく文書を先に直す」）。
- 現状の記述はすべて `release/0.1.0` 時点のコードを読んで書いた。ファイル名と行番号を付けたものは【事実】。

## 1. 何が起きているか（現状の測定）

### 1.1 同じ画面への入口が多すぎる【事実】

画面は 12 枚（`src/app/`。`_layout` を除く）。そのうち **工程の画面 5 枚に対して、到達経路が 24 本**ある。

| 行き先 | 入口の数 | 経路 |
|---|---|---|
| Editor | **11** | Home: 復旧トースト / 続きカード / 空状態カード / FAB ＋ / ⋮「編集を続ける」（`index.tsx:38, 134, 152, 92, 237`）、Episode トップ: 工程①収録 / 工程②編集 / ⋮ / テイク行 / テイク ⋮ / 下部ボタン（`episode/[id]/index.tsx:82, 88, 258, 227, 322, 244`） |
| 詳細（Details） | **4** | Home ⋮ / Episode 工程③ / Episode ⋮ / Editor ⋮ |
| 音の仕上げ（Sound） | **4** | Episode 工程④ / Episode ⋮ / Editor ⋮ / 詳細の「次へ」 |
| 書き出し（Export） | **5** | Home ⋮ / Episode 工程⑤ / Episode ⋮ / Editor ⋮ / Pack の「書き出しへ」 |

同じ場所へ何本も道があるのは、親切ではなく**現在地が分からない状態**を作る。とくに Home の `⋮`（`index.tsx:226-283`、8 項目）と Episode トップの `⋮`（8 項目）と Editor の `⋮`（5 項目）は、中身が重複しているのに並び順も文言も違う。

### 1.2 制作状況リスト（工程 5 行）が情報を持っていない【事実】

`src/app/episode/[id]/index.tsx:77-115` の 5 行:

| 行 | 遷移先 | ✓ の条件 | 問題 |
|---|---|---|---|
| ① 収録 | `editor` | テイクが 1 本以上 | ②と同じ画面 |
| ② 編集 | `editor` | 声の尺 > 0 | ①と同じ画面。①が済めば必ず ✓ |
| ③ 詳細 | `details` | タイトルと概要が空でない | テンプレート適用で最初から ✓ |
| ④ 音の仕上げ | `sound` | **`done: true` 固定**（`index.tsx:99`） | 常に ✓。情報がゼロ |
| ⑤ 書き出し | `export` | 書き出し履歴が 1 件以上 | |

5 行のうち、**実際に状態が動くのは ① と ⑤ の 2 行だけ**で、しかも遷移先は 4 種類しかない。チェックリストは「次に何をすればいいか」を指しておらず、「データが入っているか」を映しているだけ。これが「制作状況リストの不毛さ」の正体。

### 1.3 マーカーが「その場の問題」を解決していない【事実】

- 種別が 5 つ（`edit_point` / `mistake` / `interruption` / `route_change` / `topic`、`DATA_MODEL.md §4.10`）あり、**ユーザーが打つもの・システムが打つもの・テーマのチェック**が同じ ⚑ レーンに同居している（`Waveform.tsx:196-219`）。
- 収録中に「噛んだ」を押しても、その時点では何も解決しない。解決には **編集画面に戻る → バナー → 次へ → 範囲選択（4 タップ）→ 削除** が要る（`editor.tsx:353-370`, `useEditor.ts:nextMarker`）。
- 実際の収録では、噛んだらその場で言い直す。アプリが覚えるべきは「あとで見る場所」ではなく「**捨てる範囲**」。

→ **マーカー機能は廃止する**（ユーザー判断）。ただし「位置を指す」用途自体は消えないので、§5 と §6 で **構成（章）** と **収録ログ** に置き換える。

### 1.4 範囲選択が間接的すぎる【事実】

`useEditor.ts:374-396`、`editor.tsx:445-461`:

- 選択は「再生ヘッドを動かす → `ここから` を押す → 再生ヘッドを動かす → `ここまで` を押す」。**選択したいものを触らない**。
- `ここから` を押した瞬間、終端が **+1 秒（48000 smp）の決め打ち**で作られる。意図しない範囲が必ず一度できる。
- 波形の `Pressable` は `onPress` でシークするだけ（`Waveform.tsx:91-94`）。ドラッグもハンドルもピンチもない。**`react-native-gesture-handler` と `react-native-reanimated` は既に依存に入っている**（`package.json`）のに使っていない。
- 選択中のツールバーは 5 つのチップ（削除 / 録り直す / ここから / ここまで / 解除）に切り替わり、**選択を変えるもの**と**実行するもの**が同じ見た目で並ぶ。

### 1.5 素材の挿入が「その場しのぎ」になっている【事実】

- 収録中に常設されるのは **お気に入りの先頭 2 件だけ**（`editor.tsx:426-433`）。3 件目からはシートを開く（収録中に 2 タップ + スクロール）。
- 編集中の挿入位置は **再生ヘッド**。どこに入ったかは挿入後のトーストの時刻表示でしか分からない（`editor.tsx:160`）。
- 素材が 0 件のとき、シートは「素材がありません」と出すだけで**登録画面へ行けない**（`editor.tsx:490-492`）。行き止まり。
- 素材の登録（`show/assets.tsx`）への入口は、Home の小さなテキストリンクと Editor の `⋮` の 2 つ。番組の設定（`show/settings.tsx`）はさらに別。**「番組に一度登録すれば毎回の作業から消える」という設計原則（PRODUCT.md §6-4）の入口が、いちばん見つけにくい場所にある。**

### 1.6 収録前の準備をする場所が無い【事実】

- トークテーマを書ける場所は **Editor のシートだけ**（`editor.tsx:828-907`）。つまり「収録画面を開かないとテーマが書けない」。
- 追加は 1 行ずつの `TextInput`。10 項目入れるのに 10 回の送信。並べ替えは ↑ ボタンのみ（↓ がない）。
- 収録中の表示は **先頭 6 件固定・1 行省略**（`editor.tsx:375`）。長い項目は読めない。
- **台本という概念が無い。** フリートークとテーマの区別も無く、全エピソードが「空のテーマ一覧」から始まる。

## 2. 設計の芯

再設計は 5 つの原則に集約する。個別の改善案はすべてこの 5 つから導く。

### 原則 1. UI に独自の言葉を作らない

**サービス固有の言い回しはユーザーの認知負荷になり、理解のハードルを上げる。**
画面に出す言葉は、誰でも知っている一般語だけにする。設計の内部名（Outline、発話ブロック）を UI に持ち込まない。

| 使う | 使わない（今 UI に出ているもの） |
|---|---|
| 録音 / 編集 / 書き出し / 共有 | 工程（`ja.ts:246`）、したく、フェーズ |
| 録音（1 本の録音を指すときも） | テイク（`ja.ts:150,217,276,297`） |
| 素材 | Show Assets（`ja.ts:254,529,577`）、Quick Insert |
| ホーム | Home（`ja.ts:409` の「Home へ戻る」） |
| トークテーマ / 台本 / チャプター | Cue、Outline、収録スタイル |
| タイトルと概要 | メタデータ（`ja.ts:408`「すべてのメタデータをコピー」） |
| 並び順 | 声トラック（`ja.ts:277`）、タイムライン、EDL、オーバーレイ |

- ボタンは「動詞 + 目的語」の普通の形にする。**「録音を開始」「編集を続ける」「書き出す」「共有する」**。造語の動詞を作らない。
- 英語側も同じ基準（`Record` / `Edit` / `Export` / `Share` / `Topics` / `Script` / `Chapters` / `Sounds`）。`Take` は英語圏でも一般名詞ではないので UI から外す。
- 内部名（`outline_items`、`voice_segments`、`OverlayClip`）はコードとデータモデルにだけ存在してよい。**`src/i18n/` に入った瞬間に一般語かどうかを問う。**

### 原則 2. 1 エピソード = 1 画面。タブは 3 つだけ

**録音 / 編集 / 書き出し**。画面を移動せず、同じ画面の上でタブが切り替わる。
「工程が 5 つあって、それぞれ別画面」をやめる。PRODUCT.md §6-3 の「Show → Episode → 工程 の 3 段」は維持し、**工程は画面ではなくタブ**にする。

### 原則 3. 「いつ」を記録するのをやめ、「何を」で指す

マーカー（時刻のメモ）を捨てる。代わりに**トークテーマ／台本の項目を録音に焼き付ける**。
項目を次へ送った位置がチャプターの切れ目になる。ユーザーは何も打たない。編集は「3 番目のチャプターの、2 番目の塊」を指して行う。

### 原則 4. 選択は「作る」ものではなく「そこにある塊を選ぶ」もの

無音で区切られた声の塊を最小単位にする。タップ＝選択。ハンドルをドラッグ＝拡張。
`ここから` / `ここまで` は消す。

### 原則 5. 状態は一覧ではなく、次にやること 1 つ

工程チェックリストをやめる。ホームのカードは**動詞 1 つ**にする。

## 4. トークテーマと台本

### 4.1 「収録スタイル」という設定は作らない

スタイルを選ばせると、**選ぶ前に選択肢の意味を理解させることになる**。実際には選ぶ必要がない。

- **トークテーマだけ書く** → 見出しの列ができる
- **台本も書く** → その項目に本文が付く
- **何も書かない** → フリートーク。**「台本なし」という状態を作る必要はない。入力しなければそれがフリートーク。**

つまり **1 つのリストがあるだけ**。項目ごとに本文があったりなかったりしてよい（第 1 章は読み上げ原稿、第 2 章は見出しだけ、も成立する）。
モードもスタイルも設定項目も持たない。**いつでも書き足せて、いつでも消せる。**

### 4.2 どこで書くか

**録音タブ。** 収録前も収録中も収録後も、同じ場所で閲覧・編集できる。

- 録音前: このタブを開くとトークテーマの入力欄がある（項目 0 件なら「話す内容を書いておけます（任意）」）
- 録音中: 現在の項目が大きく出る。パネルを引き上げれば全項目の閲覧・追記・追加・並べ替えができる
- 録音後: そのまま残り、概要のひな形（`{{topics}}`）に差し込める

**準備のための別画面は作らない。** 今は「編集画面のシートを開かないとテーマが書けない」（`editor.tsx:828-907`）のが問題であって、専用画面が足りないわけではない。

入力はこう変える:

- **複数行をまとめて貼り付け → 改行で自動分割**（1 行ずつの送信をやめる。ここが今いちばん痛い）
- OS のキーボード音声入力はそのまま使える（FR-REC-7）
- 並べ替えはドラッグ（`react-native-gesture-handler` は依存済み）
- 項目をタップで開くと本文（台本）が書ける。空なら見出しだけの項目のまま

### 4.3 データモデル（`topics` → `outline_items`）【仮説: 列名は実装時に再検討可】

```
outline_items
  id TEXT PK
  episode_id TEXT FK
  position INTEGER
  heading TEXT            -- 見出し（トークテーマ）。必須
  body TEXT NOT NULL DEFAULT ''  -- 台本本文。空なら見出しだけの項目
  recorded_take_id TEXT nullable -- 録音中にこの項目へ進んだ位置（= チャプターの始まり）
  recorded_src_smp INTEGER nullable
  done_at INTEGER nullable
```

- **スタイルの列は持たない。** `body` が空かどうかは表示側が見るだけ。
- 既存 `topics` からの移行: `text → heading`、`checked_at → done_at`、`checked_take_id / checked_src_smp → recorded_*`、`body` は空文字で追加。**列の追加とリネームだけで済む。**
- 概要の `{{topics}}` は `heading` の箇条書きを差し込む（現行と同じ。`domain/metadata/template.ts` の入力が変わるだけ）。
- 将来の文字起こし（`transcripts`）は「チャプターごとのテキスト」として同じ構造にぶら下がる。**要約や概要の下書きの入力が最初から整う。**

### 4.4 番組の「トークテーマのひな形」

毎回同じ並びで話す番組（例: `オープニング / 今日の話題 / お便り / お知らせ / エンディング`）のために、番組に 1 つだけひな形を登録できる。新規エピソードに自動で入る。**消せるし、書き換えられる。**

これで番組画面に「毎回やることを一度だけ登録する場所」が 3 つ揃う:

1. 毎回入れる素材（オープニング / エンディング / BGM の自動配置） ← 既存
2. 概要のひな形 ← 既存
3. **トークテーマのひな形** ← 新規

PRODUCT.md §6-4「定型作業はテンプレート化」が、素材・文章・話す内容の 3 方向で完成する。

## 5. 録音タブ

### 5.1 画面（上から）

| 位置 | 要素 | 意図 |
|---|---|---|
| 1 | 状態行: `録音中 12:34` / 残り `1:52:00` / 入力デバイス（タップで切替）/ レベル | FR-REC-8/9/11 をひとまとめに。今は時計とメーターが別行で散っている |
| 2 | **話す内容（画面の主役）** | 現在の項目。本文があればスクロールして読める。左右スワイプで前後、タップで次の項目へ。引き上げると全項目 |
| 3 | 進捗 `● ● ○ ○ ○` | 残りいくつ話すかが分かる |
| 4 | 波形（小さく） | **録音中に波形は要らない。**レベルで足りる。画面の高さは読む内容に使う |
| 5 | 下部: ● 録音 / ⏸ 一時停止 / **言い直す** / 素材ボタン（お気に入り 4 件） | §5.2 / §5.3 |
| 6 | この回の録音（一覧） | 旧エピソードトップのテイク一覧。並べ替えと削除 |

項目が 0 件のときは 2 と 3 が消え、経過時間とレベルと波形だけになる。**フリートークの画面は「何も設定しなかった結果」として自然に現れる。**

### 5.2 「言い直す」— マーカーの置き換え（★重要）

噛んだときに押すボタン。押すと:

1. 候補を出す（**この項目を話し始めてから今まで** / **直近 10 秒**）
2. 選ぶと、その範囲を声の並びから外して録音を続ける
3. トーストに「取り消す」（Undo で守る。PRODUCT.md §5.2 のとおり確認ダイアログは出さない）

- 非破壊: 録音ファイルは触らない。並び（`voice_segments`）の範囲を詰めるだけ（`domain/timeline/voice.ts:deleteRange` が既にある）。**DATA_MODEL §4.8 の不変条件を壊さない。**
- 編集タブの「録り直す」（パンチイン）とは別物。**言い直す = 録音を続けたまま今のを捨てる / 録り直す = 止めた後に範囲を選んで録り直す。**
- これで「あとで直す場所を覚えておく」必要が消える。**マーカーが要らなくなる根拠はここ。**

### 5.3 素材ボタン

- お気に入り **4 件を常設**（今は 2 件、`editor.tsx:426-433`）。長押しで全件。
- 押した瞬間に挿入 + 手元で再生（現行の `insertAsset(a, 'recording')` のまま。FR-REC-5/13 の警告も維持）。
- 素材が 0 件なら、その場所に「素材を登録する ›」を置く。**行き止まりを作らない。**

### 5.4 録音中の思いつき

「話題を追加」→ リストの末尾に項目を追加（音声入力可）。現在の表示を邪魔しない。
**トークテーマ追加のやりづらさ**への答えは、§4.2 の一括入力とこれの 2 本立て。

### 5.5 割り込み・機器変更

ユーザーが打つものではないので、マーカーとは別に扱う。
→ **録音中の出来事**（`recording_events`）として記録し、編集タブではチャプターの下に細いアイコンで出す。FR-SAFE-4 / FR-SAFE-6 の「割り込み位置を示す」は維持される。

## 6. 編集タブ（選択操作の作り直し）

### 6.1 声の塊

- **無音で区切られた声の塊**を表示上の最小単位にする。UI ではこれに名前を付けない（ただ塊として見えていればよい）。
- 検出は既存の `SilenceService.planSilenceForTimeline()` を流用する（**同じ検出を「削除計画」と「分割」の両方に使う**）。設定のしきい値を変えれば分割も追従する。
- **DB には持たない**（ピークからの導出）。データモデルの追加はゼロ。

### 6.2 操作の対応表

| やりたいこと | 新 | 現状 |
|---|---|---|
| ここを消す | 塊をタップ → 選択 → ✕（または上スワイプ） | ヘッド移動 → `ここから` → 移動 → `ここまで` → `削除` |
| もう少し広く | 選択の左右ハンドルをドラッグ。隣の塊の境界にスナップ | ±1 秒の決め打ちから手探り |
| 細かく詰めたい | ハンドル長押し → 0.1 秒刻みの微調整（拡大表示つき） | ズーム + タップ |
| 聴いて確かめる | 選択を押している間だけ、前後 0.5 秒込みで再生 | 全体再生してシーク |
| 録り直す | 選択 → 「録り直す」（既存のパンチイン。FR-EDIT-5 のまま） | 同じ |
| チャプターごと消す | チャプターのラベルを長押し → まるごと選択 | 手で範囲を作る |
| 無音を詰める | 上部に「無音 12 か所・1 分 30 秒 ›」→ 件数を見て適用 | ツールバー → シート |

- ジェスチャは `react-native-gesture-handler` + `react-native-reanimated`（**依存済み**）。UI スレッドで動かすので 60 分の素材でも追従する【仮説: 実機で要測定。NFR-3】。
- 選択中のツールバーは **実行するものだけ**（削除 / 録り直す / 前に素材 / 後に素材）。選択を変える操作はツールバーから消え、波形上のハンドルに移る。

### 6.3 チャプター（マーカーレーンの置き換え）

- 波形の上に**トークテーマ由来のチャプター**を並べる（`recorded_take_id / recorded_src_smp` から解決。`domain/timeline/voice.ts:resolveTimeline` がそのまま使える）。
- タップでそこへジャンプ、長押しでまるごと選択。
- **マーカーのレーンは消える。** ⚑ / ● / ⏸ / ✓ の 4 種類の記号を読み分ける必要がなくなる。

### 6.4 素材の挿入（編集中）

- 挿入位置は**選択に対する相対**: 「前に入れる」「後に入れる」「重ねる」。再生位置まかせをやめる。
- 入れた素材はその場で素材レーンに出て、選択状態になる（音量とフェードをすぐ触れる）。
- アンカーの仕組み（`source` / `timeline_start` / `timeline_end`、DATA_MODEL §4.9）は変えない。**UI の言い方だけを「発言に付いていく / 位置を固定」にする。**

### 6.5 要件 ID の差分

## 7. 書き出しタブと「次にやること」

### 7.1 書き出しタブ = 1 画面のスクロール

工程 5 行をやめ、上から順に並べる。

1. **通して聴く** — 再生 + 「32 分 10 秒」
2. **音** — 既定のままなら 1 行「標準（-16 LUFS・BGM を自動で下げる）」。変えたい人だけ開く
3. **タイトルと概要** — ひな形の適用・トークテーマの差し込み・話数・シーズン・収録日
4. **書き出す** — 形式と品質 → 実行 → 進捗（バックグラウンドで継続、FR-EXP-4）
5. 完了 → **共有**（音声ファイルの共有 + タイトル / 概要の個別コピー。現行の Pack 画面の中身）

「次へ: 音の仕上げ」「次へ: 書き出し」のような**画面をまたぐ誘導ボタンが不要になる**。

### 7.2 ホームのカード

状態バッジ（下書き / 準備完了 / 書き出し済み）は一覧の行に小さく残すが、**カードのボタンは 1 つ**にする。

| そのエピソードの状態 | ボタン |
|---|---|
| 録音がない | **録音を開始** |
| 録音がある | **編集を続ける** |
| 書き出し済み・そのあと編集した | **書き出し直す** |
| 書き出し済み | **共有する** |

全部ふつうの日本語で、造語がない。英語側も `Start recording` / `Continue editing` / `Export again` / `Share`。

## 8. 番組画面の統合

今の `show/assets.tsx`（素材）と `show/settings.tsx`（番組情報・毎回入れる素材・概要のひな形）を **1 画面のセクション**にまとめ、ホームから「番組 ›」の 1 本で入る（§3 の図）。

素材の登録時に**試聴しながら既定の音量を決める**（`assets.default_gain_db`）。一度決めれば毎回の音量調整が消える。

## 9. 0.1.0 のスコープ【事実: ユーザー判断】

**0.1.0（未リリース）のうちに作り直す。** 作業は `release/0.1.0` を基点に行い、PR は `release/0.1.0` 宛て（DEVELOPMENT.md §2.1）。

| 0.1.0 に入れる | 0.2.0 以降 |
|---|---|
| 文言の基準と既存文言の置き換え（§2 原則 1） | 台本の読み上げ補助（文字サイズ追従・スクロール速度） |
| IA の統合・3 タブ化（§3） | 項目ごとの目安時間と実績の比較 |
| トークテーマと台本（§4） | チャプターごとの並べ替え |
| 録音タブと「言い直す」（§5） | ひな形の複数管理（Issue #60 と合流） |
| 塊の選択とチャプター（§6） | 初回起動のガイド（§11） |
| 書き出しタブとホームのカード（§7） | |
| 番組画面の統合とひな形（§4.4 / §8） | |

理由: これは機能追加ではなく**入口の整理**で、`domain/` と `services/` はほぼそのまま使える。変わるのは `src/app/` と `src/features/`。
出してから作り直すと `markers` と `topics` に実データが付いたユーザーができ、マーカー廃止が「ユーザーのデータを捨てる変更」になる。

## 11. 世界で使われるために（0.2.0 以降の布石）

- **初回起動のガイド**: 3 ステップ（番組名 → 素材を 1 つ → トークテーマのひな形）。全部飛ばせる。今は「空のホーム」から始まり、何をすればいいか分からない。
- **空の状態をすべて入口にする**: 素材 0 件、トークテーマ 0 件、エピソード 0 件のとき、必ず次の操作を置く。
- **文字起こしの接続点はトークテーマ**（§4.3）。チャプター単位のテキストとして入れば、概要の下書きも見出しの生成も同じ場所に乗る（FR-AI-2 の抽象化はそのまま使える）。
- **アクセシビリティ**: 録音タブの「話す内容」は読み上げの主対象。台本を読む用途では文字サイズ追従が必須（FR-SET-7）。
- **チャプターの書き出し**: 将来、チャプター情報を配信サービス向けに書き出す余地がある（データは既に持っている状態になる）。
