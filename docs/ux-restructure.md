# docs/ux-restructure.md — PodsNow 機能と導線の再設計（提案）

> 凡例: **【事実】** 対話で決定した仕様、またはこのリポジトリのコードを読んで確認した現状 / **【確認済み】** 公式ドキュメント等で確認済み（出典付き） / **【仮説】** 未検証・要スパイク

## 0. この文書の位置づけ

PodsNow を「自分用の収録アプリ」から「世界中の個人ポッドキャスターが最初に開く収録アプリ」へ引き上げるための、**機能と導線の再設計案**。

- 対象: 情報設計（IA）、収録前の準備、収録中の参照、編集操作、制作状況の見せ方、素材の扱い。
- この文書は **提案**。採用が決まった項目は `PRODUCT.md` / `REQUIREMENTS.md` / `DATA_MODEL.md` へ反映し、この文書は決定の経緯として残す（AGENTS.md「文書と実装が矛盾したら、コードではなく文書を先に直す」）。
- 現状の記述はすべて `release/0.1.0` 時点のコードを読んで書いた。ファイル名と行番号を付けたものは【事実】。

## 1. 何が起きているか（現状の測定）

### 1.1 同じ画面への入口が多すぎる【事実】

画面は 12 枚（`src/app/`。`_layout` を除く）。そのうち **工程の画面 5 枚に対して、到達経路が 24 本**ある。

| 行き先 | 入口の数 | 経路 |
|---|---|---|
| Editor | **11** | Home: 復旧トースト / 続きカード / 空状態カード / FAB ＋ / ⋮「編集を続ける」（`index.tsx:38, 134, 152, 92, 237`）、Episode トップ: 工程①収録 / 工程②編集 / ⋮ / テイク行 / テイク ⋮ / 下部ボタン（`episode/[id]/index.tsx:82, 88, 258, 227, 322, 244`） |
| 詳細（Details） | **4** | Home ⋮ / Episode 工程③ / Episode ⋮ / Editor ⋮ |
| 音の仕上げ（Sound） | **4** | Episode 工程④ / Episode ⋮ / Editor ⋮ / 詳細の「次へ」 |
| 書き出し（Export） | **5** | Home ⋮ / Episode 工程⑤ / Episode ⋮ / Editor ⋮ / Pack の「書き出しへ」 |

同じ場所へ何本も道があるのは、親切ではなく**現在地が分からない状態**を作る。とくに Home の `⋮`（`index.tsx:226-283`、8 項目）と Episode トップの `⋮`（8 項目）と Editor の `⋮`（5 項目）は、中身が重複しているのに並び順も文言も違う。

### 1.2 制作状況リスト（工程 5 行）が情報を持っていない【事実】

`src/app/episode/[id]/index.tsx:77-115` の 5 行:

| 行 | 遷移先 | ✓ の条件 | 問題 |
|---|---|---|---|
| ① 収録 | `editor` | テイクが 1 本以上 | ②と同じ画面 |
| ② 編集 | `editor` | 声の尺 > 0 | ①と同じ画面。①が済めば必ず ✓ |
| ③ 詳細 | `details` | タイトルと概要が空でない | テンプレート適用で最初から ✓ |
| ④ 音の仕上げ | `sound` | **`done: true` 固定**（`index.tsx:99`） | 常に ✓。情報がゼロ |
| ⑤ 書き出し | `export` | 書き出し履歴が 1 件以上 | |

5 行のうち、**実際に状態が動くのは ① と ⑤ の 2 行だけ**で、しかも遷移先は 4 種類しかない。チェックリストは「次に何をすればいいか」を指しておらず、「データが入っているか」を映しているだけ。これが「制作状況リストの不毛さ」の正体。

### 1.3 マーカーが「その場の問題」を解決していない【事実】

- 種別が 5 つ（`edit_point` / `mistake` / `interruption` / `route_change` / `topic`、`DATA_MODEL.md §4.10`）あり、**ユーザーが打つもの・システムが打つもの・テーマのチェック**が同じ ⚑ レーンに同居している（`Waveform.tsx:196-219`）。
- 収録中に「噛んだ」を押しても、その時点では何も解決しない。解決には **編集画面に戻る → バナー → 次へ → 範囲選択（4 タップ）→ 削除** が要る（`editor.tsx:353-370`, `useEditor.ts:nextMarker`）。
- 実際の収録では、噛んだらその場で言い直す。アプリが覚えるべきは「あとで見る場所」ではなく「**捨てる範囲**」。

→ **マーカー機能は廃止する**（ユーザー判断）。ただし「位置を指す」用途自体は消えないので、§5 と §6 で **構成（章）** と **収録ログ** に置き換える。

### 1.4 範囲選択が間接的すぎる【事実】

`useEditor.ts:374-396`、`editor.tsx:445-461`:

- 選択は「再生ヘッドを動かす → `ここから` を押す → 再生ヘッドを動かす → `ここまで` を押す」。**選択したいものを触らない**。
- `ここから` を押した瞬間、終端が **+1 秒（48000 smp）の決め打ち**で作られる。意図しない範囲が必ず一度できる。
- 波形の `Pressable` は `onPress` でシークするだけ（`Waveform.tsx:91-94`）。ドラッグもハンドルもピンチもない。**`react-native-gesture-handler` と `react-native-reanimated` は既に依存に入っている**（`package.json`）のに使っていない。
- 選択中のツールバーは 5 つのチップ（削除 / 録り直す / ここから / ここまで / 解除）に切り替わり、**選択を変えるもの**と**実行するもの**が同じ見た目で並ぶ。

### 1.5 素材の挿入が「その場しのぎ」になっている【事実】

- 収録中に常設されるのは **お気に入りの先頭 2 件だけ**（`editor.tsx:426-433`）。3 件目からはシートを開く（収録中に 2 タップ + スクロール）。
- 編集中の挿入位置は **再生ヘッド**。どこに入ったかは挿入後のトーストの時刻表示でしか分からない（`editor.tsx:160`）。
- 素材が 0 件のとき、シートは「素材がありません」と出すだけで**登録画面へ行けない**（`editor.tsx:490-492`）。行き止まり。
- 素材の登録（`show/assets.tsx`）への入口は、Home の小さなテキストリンクと Editor の `⋮` の 2 つ。番組の設定（`show/settings.tsx`）はさらに別。**「番組に一度登録すれば毎回の作業から消える」という設計原則（PRODUCT.md §6-4）の入口が、いちばん見つけにくい場所にある。**

### 1.6 収録前の準備をする場所が無い【事実】

- トークテーマを書ける場所は **Editor のシートだけ**（`editor.tsx:828-907`）。つまり「収録画面を開かないとテーマが書けない」。
- 追加は 1 行ずつの `TextInput`。10 項目入れるのに 10 回の送信。並べ替えは ↑ ボタンのみ（↓ がない）。
- 収録中の表示は **先頭 6 件固定・1 行省略**（`editor.tsx:375`）。長い項目は読めない。
- **台本という概念が無い。** フリートークとテーマの区別も無く、全エピソードが「空のテーマ一覧」から始まる。

## 2. 設計の芯

再設計は 4 つの原則に集約する。個別の改善案はすべてこの 4 つから導く。

### 原則 1. 1 エピソード = 1 ワークスペース。フェーズは 3 つだけ

**したく → 収録 → 仕上げ**。画面を移動せず、同じ画面の上でフェーズが切り替わる。
「工程が 5 つあって、それぞれ別画面」をやめる。PRODUCT.md §6-3 の「Show → Episode → 工程 の 3 段」は維持するが、**工程は画面ではなくフェーズ**にする。

### 原則 2. 「いつ」を記録するのをやめ、「何を」で指す

マーカー（時刻のメモ）を捨てる。代わりに **構成（話す項目）を録音に焼き付ける**。
項目を「次へ」した瞬間が章の切れ目になる。ユーザーは何も打たない。編集は「第 3 章の 2 番目のブロック」を指して行う。

### 原則 3. 選択は「作る」ものではなく「そこにある塊を選ぶ」もの

無音で区切られた**発話ブロック**を最小単位にする。タップ＝選択。ハンドルをドラッグ＝拡張。
`ここから` / `ここまで` は消す。

### 原則 4. 状態は一覧ではなく「次の一手」

工程チェックリストをやめ、**次にやること 1 つ**だけを出す。

## 3. 新しい情報設計（IA）

```
Home（番組ハブ）
│  ├ 次の一手カード（1 枚）
│  ├ エピソード一覧
│  └ 番組 ›
│
├ Episode Workspace  ── したく / 収録 / 仕上げ（同一画面・上部セグメント）
│     └ 書き出しシート → 完了で Distribution Pack
│
├ Show（番組）
│     ├ 素材（Opening / Ending / ジングル / SE / BGM）
│     ├ 構成テンプレート（★新規）
│     ├ 概要欄テンプレート
│     └ 番組情報（名前・著者・Cover Art・既定シーズン）
│
├ 設定
└ 復元（.podsnow）
```

**画面数 12 → 7。工程画面への到達経路 24 → 7。**

| 廃止するもの | 行き先 |
|---|---|
| Episode トップ（`episode/[id]/index.tsx`） | Workspace の「したく」と「仕上げ」へ吸収。テイク一覧は「したく」の下部へ |
| Editor の `⋮`（more シート） | フェーズのセグメントが役目を果たす |
| 詳細画面（`details.tsx`） | 「仕上げ」フェーズのセクションへ |
| 音の仕上げ画面（`sound.tsx`） | 同上（既定のままなら 1 行に畳む） |
| 書き出し画面（`export.tsx`） | 「仕上げ」からのシート。完了で Pack へ |
| Home の `⋮` の工程メニュー | 行タップ = Workspace。`⋮` は複製 / バックアップ / 音声を削除 / 削除 の 4 つだけ |
| Show への 2 系統の入口 | Home の「番組 ›」1 本に統合（`show/assets.tsx` と `show/settings.tsx` を 1 画面のセクションに） |

**Home からの録音開始は 2 タップ**（＋ → ● 録音）。PRODUCT.md §8 の「3 タップ以内」は維持どころか縮む。

## 4. 収録スタイルと構成（Outline）— 新しい中心概念

### 4.1 3 つのスタイルは「別の機能」ではなく「同じモデルの粒度」

| スタイル | 構成データ | 収録中の表示 |
|---|---|---|
| **フリートーク** | 項目 0 件 | 経過時間・レベル・素材パッドのみ |
| **トークテーマ** | 見出しの列 | 現在のテーマを大きく 1 件 + 次の予告 |
| **台本** | 見出し + 本文 | 本文をプロンプター表示（大きな文字・既読を淡く） |

**実装上は 1 つのモデル**。台本は「本文がある項目」、テーマは「本文が空の項目」、フリートークは「項目が 0 件」。
分岐をデータに持ち込まない（分岐は表示側の 1 つの三項演算で済む）。

### 4.2 データモデル（`topics` → `outline_items`）【仮説: 列名は実装時に再検討可】

```
outline_items
  id TEXT PK
  episode_id TEXT FK
  position INTEGER
  heading TEXT            -- 見出し（テーマ名）。必須
  body TEXT               -- 台本本文。空文字ならテーマモード
  planned_duration_smp INTEGER nullable   -- 目安の長さ（任意）
  recorded_take_id TEXT nullable          -- 収録中に「次へ」した位置（= 章の始まり）
  recorded_src_smp INTEGER nullable
  done_at INTEGER nullable
```

- `episodes.outline_style TEXT`（`free` / `topics` / `script`）。既定は**前回そのユーザーが選んだもの**。
- 既存の `topics` からの移行: `text → heading`、`checked_at → done_at`、`checked_take_id/checked_src_smp → recorded_*`。**破壊的変更ではなく列の追加とリネームで済む。**
- 概要欄の `{{topics}}` は `heading` の箇条書きを差し込む（現行と同じ。`domain/metadata/template.ts` の入力が変わるだけ）。
- 将来の文字起こし（`transcripts`）は「章ごとのテキスト」として同じ構造にぶら下がる。**AI 要約の入力が最初から整う。**

### 4.3 Show の「構成テンプレート」（★新規）

番組の定型の並び（例: `オープニング挨拶 / 今日のテーマ / お便り / お知らせ / エンディング`）を Show に 1 つ登録しておく。新規エピソードで自動適用。

これで Show 画面に**「毎回やることを一度だけ登録する場所」が 3 つ揃う**:

1. 素材（Opening / Ending / BGM の自動配置） ← 既存
2. 概要欄テンプレート ← 既存
3. **構成テンプレート** ← 新規

PRODUCT.md §6-4「定型作業はテンプレート化」が、素材・文章・構成の 3 方向で完成する。

### 4.4 「したく」フェーズの UI

1. **スタイル選択**（3 枚のカード。既定は前回の選択）
2. **項目の入力**
   - **複数行の一括貼り付け → 改行で自動分割**（1 行ずつの送信をやめる。ここが今いちばん痛い）
   - OS のキーボード音声入力はそのまま使える（FR-REC-7）
   - 並べ替えはドラッグ（`react-native-gesture-handler` は依存済み）
   - 各項目に目安時間（任意）→ 合計を表示「およそ 28 分」
3. **テンプレートから読み込む** / **この構成をテンプレートに保存**
4. 下部に「録音をはじめる」（＝ 収録フェーズへ）

素材と構成の既定適用の結果（Opening が入っている、BGM が敷かれている）もここに 1 行で出す。**「何が自動で入ったか」が収録前に分かる。**

## 5. 収録フェーズ（Cue 表示）

### 5.1 画面（上から）

| 位置 | 要素 | 意図 |
|---|---|---|
| 1 | 状態行: `REC 12:34` / 残り録音可能 `1:52:00` / 入力デバイス（タップで切替）/ レベルメーター | FR-REC-8/9/11 をひとまとめに。現状は時計とメーターが別行で散っている |
| 2 | **Cue カード（画面の主役）** | 現在の項目。台本なら本文をスクロール。左右スワイプで前後、タップで「この項目を終える → 次へ」 |
| 3 | 進捗 `● ● ○ ○ ○` + 経過/目安 | 残りいくつ話すかが分かる |
| 4 | 波形（小さく） | **収録中に波形は要らない。**レベルメーターで足りる。画面の高さは Cue に使う |
| 5 | 下部バー: ● 録音 / ⏸ 一時停止 / **↺ やり直し** / 素材パッド（お気に入り 4 件常設） | §5.2 / §5.3 |

### 5.2 「やり直し」— マーカーの置き換え（★重要）

噛んだときに押すボタン。押すと:

1. 直近の候補（**この項目の始まりから今まで** / **直近 10 秒**）を提示
2. 選ぶと、その範囲を**声トラックから外して**録音を続ける
3. トーストに「取り消す」（Undo で守る。PRODUCT.md §5.2 の方針どおり確認ダイアログは出さない）

- 非破壊: Take の WAV は触らない。`voice_segments` の範囲を詰めるだけ（`domain/timeline/voice.ts:deleteRange` が既にある）。**DATA_MODEL §4.8 の不変条件を壊さない。**
- これで「あとで直す場所を覚えておく」必要が消える。**マーカーが要らなくなる根拠はここ。**

### 5.3 素材パッド

- お気に入り **4 件を常設**（現状 2 件）。長押しで全件シート。
- 押した瞬間に挿入イベント + モニター再生（現行の `insertAsset(a, 'recording')` のまま。FR-REC-5/13 の警告も維持）。
- 素材が 0 件なら、パッドの位置に「素材を登録する ›」を置く。**行き止まりを作らない。**

### 5.4 収録中の思いつき

「あとで話す」ボタン → Outline の末尾に項目を追加（音声入力可）。Cue の流れを邪魔しない。
**トークテーマ追加のやりづらさ**への答えは、「したく」での一括入力（§4.4）とこれの 2 本立て。

### 5.5 割り込み・機器変更

ユーザーが打つものではないので、マーカーとは別扱いにする。
→ **収録ログ**（`recording_events`）として記録し、編集画面では章レーンの下に細いアイコンで出す。FR-SAFE-4 / FR-SAFE-6 の「割り込み位置を示す」は維持される。

## 6. 編集フェーズ（選択操作の作り直し）

### 6.1 発話ブロック（utterance）

- **無音で区切られた声の塊**を表示上の最小単位にする。
- 検出は既存の `SilenceService.planSilenceForTimeline()` の結果を流用する（**同じ検出を「削除計画」と「分割」の両方に使う**）。設定のしきい値を変えれば分割も追従する。
- **DB には持たない**（ピークからの導出）。データモデルの追加はゼロ。

### 6.2 操作の対応表

| やりたいこと | 新 | 現状 |
|---|---|---|
| ここを消す | ブロックをタップ → 選択 → ✕（または上スワイプ） | ヘッド移動 → `ここから` → 移動 → `ここまで` → `削除` |
| もう少し広く | 選択の左右ハンドルをドラッグ。隣のブロック境界にスナップ | ±1 秒の決め打ちから手探り |
| 細かく詰めたい | ハンドル長押し → 0.1 秒刻みの微調整（拡大表示つき） | ズーム + タップ |
| 聴いて確かめる | 選択を押している間だけ、前後 0.5 秒込みで再生 | 全体再生してシーク |
| 録り直す | 選択 → 「録り直す」（既存のパンチイン。FR-EDIT-5 のまま） | 同じ |
| 章ごと消す | 章ラベルを長押し → その章が選択される | 手で範囲を作る |
| 無音を詰める | 上部バナー「無音 12 か所・1 分 30 秒 ›」→ プレビュー → 適用 | ツールバー → シート |

- ジェスチャは `react-native-gesture-handler` + `react-native-reanimated`（**依存済み**）。UI スレッドで動かすので 60 分素材でも追従する【仮説: 実機で要測定。NFR-3】。
- 選択中のツールバーは **実行するものだけ**（削除 / 録り直す / 前に素材 / 後に素材）。選択を変える操作はツールバーから消え、波形上のハンドルに移る。

### 6.3 章レーン（マーカーレーンの置き換え）

- 波形の上に **Outline 由来の章ラベル**を並べる（`recorded_take_id/src_smp` から解決。`domain/timeline/voice.ts:resolveTimeline` がそのまま使える）。
- タップでその章へジャンプ、長押しで章を丸ごと選択。
- **マーカーのレーンは消える。** ⚑ / ● / ⏸ / ✓ の 4 種類の記号を読み分ける必要がなくなる。

### 6.4 素材の挿入（編集中）

- 挿入位置は **選択に対する相対**: 「前に入れる」「後に入れる」「重ねる」。再生ヘッド依存をやめる。
- 挿入した素材はその場で波形の素材レーンに出て、選択状態になる（音量とフェードをすぐ触れる）。
- アンカーの仕組み（`source` / `timeline_start` / `timeline_end`、DATA_MODEL §4.9）は変えない。**UI の言い方だけを「発言に付いていく / 位置に固定」にする。**

### 6.5 要件 ID の差分

| ID | 変更 |
|---|---|
| FR-REC-4（収録中のマーカー） | **廃止** → FR-REC-4'「やり直し（直近の範囲を捨てて続ける）」 |

### 6.6 データモデルの差分

| 対象 | 変更 |
|---|---|

## 7. 仕上げフェーズと「次の一手」

### 7.1 仕上げ = 1 画面のスクロール

工程 5 行をやめ、上から順に並べる。

1. **聴き通す** — プレビュー再生 + 「32 分 10 秒」
2. **音** — 既定のままなら 1 行「標準（-16 LUFS・ダッキングあり）」。触りたい人だけ開く
3. **情報** — タイトル / 概要（テンプレート適用・`{{topics}}` 差し込み）/ 話数 / 季 / 収録日
4. **書き出す** — プリセット → 実行 → 進捗（バックグラウンド継続、FR-EXP-4）
5. 完了 → **Distribution Pack**（現行のまま。個別コピー + 共有）

「次へ: 音の仕上げ」「次へ: 書き出し」のような**画面をまたぐ誘導ボタンが不要になる**。

### 7.2 Home の「次の一手」カード

状態バッジ（Draft / Ready / Exported）は一覧の行に小さく残すが、**カードは動詞 1 つ**にする。

| そのエピソードの状態 | カードのボタン |
|---|---|
| 構成も録音もない | **したくをする** |
| 構成はある、録音がない | **録音をはじめる** |
| 録音がある | **続きを編集** |
| 書き出し済み・その後に編集あり | **書き出し直す** |
| 書き出し済み | **配信用にコピー**（Pack へ直行） |

「何をすればいいか」をアプリが 1 つだけ提案する。判断を一覧に投げ返さない。

## 8. Show（番組）画面の統合

現在の `show/assets.tsx`（素材）と `show/settings.tsx`（番組情報・既定構成・概要テンプレート）を **1 画面のセクション**にまとめ、Home から「番組 ›」の 1 本で入る。

```
番組
├ 番組情報      名前 / 著者 / Cover Art / 既定シーズン
├ 毎回の構成     Opening ▸ / Ending ▸ / BGM ▸（音量・ダッキング）
├ 構成テンプレート  見出しの並び（★新規）
├ 概要欄テンプレート {{title}} {{episode_number}} {{topics}} …
└ 素材          Opening / Ending / ジングル / SE / BGM（登録・試聴・★・並べ替え）
```

素材の登録時に**既定音量をその場で試聴しながら決める**（`assets.default_gain_db`）。一度決めれば毎回の音量調整が消える。

## 9. 0.1.0 との関係 — どこまでを今やるか

**推奨: 0.1.0 のスコープを「収録の筋」に絞って作り直してから出す。**

| 今やる（0.1.0） | 後でよい（0.2.0） |
|---|---|
| IA の統合（§3） | 台本のプロンプター補助（速度追従・文字サイズ） |
| Outline（§4.1-4.2）とフリートーク/テーマ | 構成テンプレートの複数管理（Issue #60 と合流） |
| Cue 表示と「やり直し」（§5） | 項目ごとの目安時間と実績の比較 |
| ブロック選択（§6.1-6.2） | 章ごとの並べ替え |
| 次の一手（§7.2） | オンボーディング（§11） |
| マーカー撤去（§6.3, §6.5） | |

理由:

1. これは機能追加ではなく **同じ機能の入口の整理**。今あるサービス層（`services/`）と純粋ドメイン（`domain/`）はほぼそのまま使える。変わるのは `src/app/` と `src/features/` の配置。
2. **出してから作り直すと移行コストが乗る。** `markers` と `topics` に実データが付いたユーザーができる。マーカー廃止は「ユーザーが打ったデータを捨てる」変更になり、配布後にやるには重い。
3. 世界に出すつもりなら、**最初のバージョンの構造が評価の対象**になる。収録アプリは「2 回目に開くか」で決まる。

## 11. 世界で使われるために（0.2.0 以降の布石）

- **オンボーディング**: 初回起動で 3 ステップ（番組名 → 素材を 1 つ → 構成テンプレート）。全部スキップ可。今は「空の Home」から始まり、何をすればいいか分からない。
- **用語を UI から追い出す**: `Take` / `オーバーレイ` / `EDL` は実装の言葉。UI は「録音」「素材」「章」。i18n の英語側も同じ基準で見直す（`Take` は英語圏でも一般名詞ではない）。
- **空状態をすべて入口にする**: 素材 0 件、構成 0 件、エピソード 0 件のとき、必ず次の操作を置く。
- **文字起こしの接続点は Outline**（§4.2）。章単位のテキストとして入れば、概要欄の下書きも章の見出し生成も同じ場所に乗る（FR-AI-2 の抽象化はそのまま使える）。
- **アクセシビリティ**: Cue カードは読み上げの主対象。台本モードは文字サイズ追従が必須（FR-SET-7）。
