PodsNow の次のデザインをどちらへ進めるか

今のデザインは「グラファイトの面、明るい文字、ひとつのシトロン」を基本に、ボタンにだけ硬い影を付けたネオブルータリズムを加えています（#105 / #110）。ここからさらに進める道として、次の 2 つを比べました。

Aネオブルータリズムを強めて、カラフルでフラットなポップさを押し出す　B録音機材としての楽しさを、スキューモーフィズムで作り込む

どちらも、実際の録音タブの情報構造（状態 → 時間 → レベル → 入力 → 話すこと → ジングル → 操作バー）は変えずにモックにしています。3 つ目の案は、両方を部分的に組み合わせた案です。その後、共有してもらったムードボードをもとに、4 つ目の案 D を足しました。いまの推奨は D です。

ムードボードから：D「カラー成形のレコーダー」

共有してもらった 9 枚には、A と B の両方が入っていました。たまごっち、ポケットピカチュウ、スポーツ系のカセットプレーヤー、色とりどりの MD。どれも色はポップで平ら、形は触れる道具です。つまり A か B かではなく、「金属と光沢のリアルな機材」でもなく、色つきプラスチックで成形された、おもちゃ寄りの録音機という第 4 の道が見えます。

成形色の本体イエロー、ミント、クリアブルー。塗装や金属ではなく、プラスチックそのものの色
バックライトの液晶窓緑やオレンジの地にドットの文字。黒いベゼルで囲む（たまごっち、オシロスコープ、FIELD COM）
本体に印刷された小さなラベルHOLD、INPUT、PLAY/PAUSE。操作の名前がそのまま装飾になる
ラベルを貼るメディアカセットや MD のラベル。エピソード 1 本を「1 枚のディスク」として扱える
ラジオ局のスタジオON AIR ランプ、スタジオ時計、色つきのフェーダーキャップ。これから話すという緊張感を作る

ポケットに、1 台の録音スタジオ

LP やアイキャッチは A のネオブルータリズム（太い輪郭、硬い影、原色）で組み、主役として D の本体を並べます。平らなグラフィックの中に置くと、本体の色がそのまま商品写真の役割を果たします。

最初の比較（A / B / C）

ムードボードをもらう前に作った 3 案です。D は、C の「機材感は録音デッキに集中させる」を広げ、A の色を本体色として取り込んだ案になっています。

どちらの案でも変えないこと

意味の色（§5.2）録音はコーラル、削除はローズ、BGM はライラック、差し込みは青。飾りに使えば意味が薄れる
判断の優先順位（§1.3）音声が守られていることと状態を正しく伝えることが先、装飾は最後
OS の標準部品（§6.2）ナビゲーション・メニュー・シート・スイッチは OS の部品。自前で描くのは Transport・波形・メーター・ボタン・カード
測れる色（§5.3 / §5.5）275 組のコントラストを生成時と CI で測る。透過や背面が決まらない色は使わない

推奨と次の一歩（ムードボードを受けて更新）

D を推します。A と B のどちらかを選ぶ必要はありません。ムードボードの物は、色はポップで平ら（A）、形は触れる道具（B）です。この組み合わせなら、アプリの中では録音への期待感を B で作り、LP・アイキャッチ・ストア画像では A の強いグラフィックに本体を並べる、という役割分担ができます。

「男の子には B、女の子には A」という見立てについて。ムードボードのたまごっちやポケットピカチュウ、色とりどりの MD は、性別を問わずに愛された物です。ターゲットを分ける軸は性別よりも「おもちゃ寄りか、本格機材寄りか」のほうが扱いやすく、D はこの軸を本体色で調整できます。イエローやミントはおもちゃ寄り、ネイビーやグラファイトは機材寄りです。

今の規則との関係は次のとおりです。

  • 意味の色と本体色を分ける。本体色は「素材の色」という別の系統にし、状態を表すのには使わない。録音のコーラルと削除のローズの色相には本体色を置かない（真っ赤な本体は作らない）
  • 透明なスケルトンは透過で作らない。中の基板は不透明な絵として描く（§5.5）。液晶の走査線も、同じ理由でトークン化した不透明な模様にする
  • 本体色ごとにコントラストを測る。ramps.py に本体色を 1 本ずつのランプとして足し、印刷ラベル・液晶の文字・キーの輪郭を測る。本体色を増やすほど、検査する組み合わせも増える
  • 数字の書体を決め直す。液晶のドット書体（例：DotGothic16、SIL OFL）を時間の表示にだけ使うかどうかを決める。#110 で数字を Manrope に揃えた判断を、液晶窓の中だけ例外にするかどうか【仮説】
  1. Issue を立てる：「D：カラー成形のレコーダーをブランドとアプリの方向にする」。まず DESIGN_SYSTEM.md の §2（アートディレクション）と、assets/brand/README.md の変更案を書く
  2. 録音タブ 1 画面だけ試作する：液晶窓・ON AIR ランプ・成形キーを、Development Build で iOS と Android の両方に描く。boxShadow の inset が 0.86 で使えるか【仮説・要確認】もここで確かめる
  3. 本体色は 2 色から始める：ライトはイエロー、ダークはネイビー。着せ替えは 3 色目を足すときに設定へ出す
  4. アイコンと LP のラフを作る：scripts/brand/geometry.py に液晶窓の中の 2 段ロゴを足す案として検討する
  5. 既存のブランドに似せない：参考画像にはソニーや任天堂の製品が含まれる。ロゴの位置、ボタンの配置、特徴的な形はまねず、「色つきプラスチック＋液晶＋印刷ラベル」という要素だけを借りる

モックは方向性を比べるための HTML/CSS のスケッチです。色はトークン生成（ramps.py）を通していないため、コントラストは測っていません。実装する画面の値ではありません。
