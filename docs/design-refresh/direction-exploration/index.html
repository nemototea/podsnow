PodsNow の次のデザインをどちらへ進めるか

今のデザインは「グラファイトの面、明るい文字、ひとつのシトロン」を基本に、ボタンにだけ硬い影を付けたネオブルータリズムを加えています（#105 / #110）。ここからさらに進める道として、次の 2 つを比べました。

Aネオブルータリズムを強めて、カラフルでフラットなポップさを押し出す　B録音機材としての楽しさを、スキューモーフィズムで作り込む

どちらも、実際の録音タブの情報構造（状態 → 時間 → レベル → 入力 → 話すこと → ジングル → 操作バー）は変えずにモックにしています。3 つ目の案は、両方を部分的に組み合わせた推奨案です。

どちらの案でも変えないこと

意味の色（§5.2）録音はコーラル、削除はローズ、BGM はライラック、差し込みは青。飾りに使えば意味が薄れる
判断の優先順位（§1.3）音声が守られていることと状態を正しく伝えることが先、装飾は最後
OS の標準部品（§6.2）ナビゲーション・メニュー・シート・スイッチは OS の部品。自前で描くのは Transport・波形・メーター・ボタン・カード
測れる色（§5.3 / §5.5）275 組のコントラストを生成時と CI で測る。透過や背面が決まらない色は使わない

推奨と次の一歩

C を推します。B の作り込み（ワクワクする機材感）を、録音デッキ 1 か所に集中させる案です。A のポップな色は、意味を持つ編集レーンでだけ使います。PodsNow の気持ちが最も高まるのは「録り始める瞬間」で、ずっと見ているのは録音中の時間・レベル・操作の 3 つです。凝った作りはそこに集め、ほかの画面は OS の部品と静かなグラファイトのままにしておくと、デッキが引き立ちます。

A を全画面に広げると、今の色の仕組み（意味の色を 30° 以上離して配置し、コントラストを測って生成する）と、真正面からぶつかります。B を全画面に広げると、#98 で OS 標準部品に戻した方針と、ライト・ダークの両立にかかる工数とぶつかります。

  1. Issue を 1 つ立てる：「録音デッキ（Transport + 時間 + メーター）を機材として作り込む」。先に DESIGN_SYSTEM.md の §2 と §6 に、デッキの例外と、使ってよい質感（グラデーションは機体だけ、文字は平らな地に置く）を書く
  2. 技術を確認する：RN 0.86 で boxShadow の inset とグラデーションが iOS と Android で描けるかを、docs と Development Build で確認する。LED の段は、レベルの更新頻度でも描画が詰まらないかを測る
  3. 色を足す：液晶の地とデッキの機体を、ramps.py に不透明なトークンとして追加し、液晶上の文字を 4.5:1 で測る
  4. 編集レーンに A を試す：声・BGM・差し込みのクリップを、平らな色と墨の輪郭で描く
  5. 実機で確認する（未検証）：屋外の明るさ、最大文字サイズ、動きを減らす設定で、キーの押し込みとランプが過剰でないか

モックは方向性を比べるための HTML/CSS のスケッチです。色は案 C 以外、トークン生成（ramps.py）を通していないため、コントラストは測っていません。実装する画面の値ではありません。
