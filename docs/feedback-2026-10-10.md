## 1. 番組情報を「見せる」画面にする

**現状【事実】**

- 番組画面（`src/app/show/index.tsx`）の頭に出すのは、アートワーク・番組名・著者・本数だけ。
  概要（`shows.description`）は鉛筆を押して開く編集シートでしか見えない。
- 取り込みで入る Web サイト・カテゴリー・言語・著作権表記・支援リンク（FR-SHOW-3a）は、どの画面にも出ていない。

**提案【提案】** Spotify / Apple Podcasts の番組ページと同じ作り。

- 著者の行の下に**概要を 3 行で省略表示**し、押すと全文に広がる（「もっと見る」）。HTML は `htmlToPlainText` を通す。
- その下に**番組の詳細**（カテゴリーのチップ、Web サイト、言語）を、値のあるものだけ出す。リンクは押すと開く。
- 編集は今の鉛筆（`a11yEditShowInfo`）のまま。シートの項目は、取り込みで入る項目まで広げるかを決める（少なくとも Web サイトとカテゴリー）。
- 番組情報が空のとき（取り込みも手入力もしていない）は、概要の所に「番組の紹介を書く」を出して編集シートへ誘う。
- 見た目は見本（`docs/design-refresh/ds4/mock.html`）に無いので、**先に見本へ足してから**実装する（AGENTS.md）。

## 2. 取り込んだ情報をひな形に反映するか

**結論【提案】:** 反映する価値はあるが、**番組の概要をそのまま入れるのではなく、回の概要の共通部分を候補として出し、確認してから入れる**のがよい。

**理由**

- 番組の概要（channel の `description`）は「番組の紹介」で、毎回の概要欄に入れる文ではない。番組画面に出せば足りる（§1）。
- 毎回の概要欄に同じく入っているのは、たいてい**末尾の定型**（お便りフォーム、SNS、ハッシュタグ、BGM のクレジット）。
  取り込んだ `feed_episodes` の直近 N 回（例: 5 回）の概要から、**共通する行**を取り出せば、そのまま概要欄テンプレートの候補になる【仮説: 共通部分の抽出規則と N】。
- カンペのひな形（FR-SHOW-4）は RSS から作る材料が無いので対象外。

**守ること**

- 取り込み画面のプレビューで「この内容を概要欄のひな形にする」を見せ、**選んだときだけ**書く（黙って上書きしない。`docs/podcast-import-cases.md` P3）。
- 今のテンプレートが空（または初期値のまま）のときだけ既定で選んでおく。手で書いたテンプレートがあれば既定は選ばない。
- 読み込み直し（`previewRefresh`）では出さない。PodsNow だけの設定は触らない（同文書 §6 #139 の決定）。
- 純粋な抽出処理は `src/domain/` に置き、Jest で網羅する。

## 3. 間違った番組を取り込んだときに直せない

**なぜ上書きできないのか【事実】**

仕様上の理由は 2 つある。

1. **配信済みの回と話数の台帳が混ざるのを防ぐため。** 取り込みは番組情報だけでなく、配信済みの回（`feed_episodes`）・Apple の番組 ID・カテゴリーも書く。
   別の番組で上書きすると、A の回と B の回が台帳に並び、新しいエピソードの話数が A と B の最新の続きになって壊れる
   （`docs/podcast-import-cases.md` B-1 / D-1。以前は実際に混ざっていた）。
2. **別の番組は「差し替え」ではなく「番組の追加」で扱うと決めたため。** 一般公開版は複数の番組を持てる（FR-SHOW-1、同文書 Q2、ユーザー判断 2026-09-26）。
   MVP は番組が 1 つなので、それまでの間は別の番組の取り込みを拒否している（`PodcastImportService.commit` の `import_other_show`）。

**抜けている所【事実】**

- 拒否の理由は正しいが、**最初の取り込みで間違えた場合**の逃げ道が無い。最初の取り込みは確認なしで通る（`feed_imported_at` が空なので判定は `new`）ため、
  間違えた番組が「今の番組」になり、正しい番組を取り込もうとすると `different` で拒否される。
- 同文書 A-1 には「取り込み後も元に戻せるようにする（B-1 の差し替えと同じ仕組み）」とあるが、実装されていない。

**決定【事実: ユーザー判断 2026-10-10】**

- 取り込みの解除は、実質「今の番組情報を消して、別の番組を取り込めるようにする」操作として扱う。**手で直した番組名・概要も残さない。**
- 解除の確認で、**手で編集した番組名・概要も消える（次の取り込みで上書きされる）ことを警告する。**
- 話数は**配信済みの回が常に正**。手元の収録中のエピソードに振ってある話数は解除で触らない（書き出すときに直せる。自己責任）。

**案【提案】**

- 番組画面の「…」に **「番組の取り込みを解除」** を置く。解除は B-1 の差し替えで決めていた範囲を消す:
  `feed_episodes`・外部 ID・カテゴリー・支援リンク・取り込んだアートワーク・`feed_url` / `podcast_guid` / `feed_imported_at`。
  加えて番組情報（番組名・概要・著者・Web サイト・言語・著作権表記・所有者など）も消す。番組名は初期値（`ServiceLabels` の仮の番組名）に戻す。
  **手元で作ったエピソード（録音）と、PodsNow だけの設定（素材・既定の構成・カンペのひな形・概要欄テンプレート）は消さない。**
- 確認文は数字と中身で伝える（「番組名・概要（手で編集した内容を含む）と、配信済みの回 120 本の記録を消します。録音したエピソードは残ります」）。破壊的な操作なので `confirmDestructive`。
- 解除のあとは判定が `new` に戻るので、正しい番組をそのまま取り込める。複数の番組（#64）が入っても、この操作は「取り込んだ情報を外す」として残せる。
- 取り込み画面で `different` を拒否するときの文言にも、解除の場所を添える（「番組画面の … から取り込みを解除できます」）。
- 手元のエピソードの話数はそのまま（上の決定）。解除のあと新しく作るエピソードの話数は、次に取り込んだ番組の配信済みの回の続きになる。
- 話数の台帳（`feed_episodes`）を消すので、`data-safety` 扱いでテストと一緒に変える。

## 4. 省略表示が抜けている所

ほとんどの行は `numberOfLines` が付いているが、次は抜けている（【事実】はコードで確認、崩れ方は【仮説】）。

| 場所 | 中身 | 起きること | 直し方 |
|---|---|---|---|
| `src/ui/components.tsx` `Chip` | ラベル | 長い素材名（番組画面の「毎回入れる素材」の枠は素材名をチップに出す）で、横の試聴ボタンと音量の ± を押し出す | `numberOfLines={1}` と `flexShrink: 1`。チップ自体に `maxWidth` |
| `src/app/show/index.tsx` 番組画面の著者 | 著者名 | `numberOfLines={1}` はあるが `flexShrink` が無く、長い著者名で「· N 本」が画面外へ出る | 著者の `Text` に `flexShrink: 1` |
| 同 番組名 | `typography.display` | 行数の上限が無い。長い番組名でアートワークの下が大きく伸びる | `numberOfLines={3}` 程度 |
| `src/ui/Sheet.tsx` / `Sheet.ios.tsx` | 題・副題 | 素材名を含む題（「OP の素材」など）で ✕ と並ぶ | 題は 2 行、副題は 1 行で省略 |
| `src/features/episode/OverlayBar.tsx`（#254 で追加） | 帯の素材名 | `numberOfLines={1}` あり。対応済み | — |
| `src/ui/components.tsx` `Pill` / `Segmented` | ラベル | 英語表示で長くなると折り返して形が崩れる | 1 行で省略 |
| `src/ui/components.tsx` `Notice` / `Toast` | 本文 | 折り返すので崩れはしない。対応不要 | — |

**横スクロールについて【提案】**

- 文字の横スクロール（マーキー）は**再生中の題名など、主役の 1 行だけ**に限るのがよい。iOS / Android とも一覧の行で動く文字は一般的でなく、
  読み上げや「視差効果を減らす」（`useReducedMotion`）とも相性が悪い。
- 候補はミニプレーヤー・プレーヤー画面の題名（Spotify と同じ）。動かすのは表示されて少し待ってから、`useReducedMotion` が有効なら省略に戻す。
- それ以外の行は「…」で省略し、全文は押した先（詳細・編集シート）で見せる。省略した行は `accessibilityLabel` で全文を読む。

## 5. 「話す間は BGM を下げる」

**現状【事実】**（`src/features/episode/ExportTab.tsx`）

- BGM が無いと、保存されている値に関係なく**外れた表示**になり、値の所に「BGM を入れる」が出る。押すと `onGoEdit` で収録タブへ移る。
- 実際の値（`sound.ducking.enabled`）は BGM の有無と関係なく保存されている。表示と保存が食い違っている。

**提案【提案】:** 指摘のとおり、**BGM の有無にかかわらず切り替えられる設定**にする。

- チェックは保存されている値をそのまま出し、押すと入・切が替わる（画面は移らない）。
- BGM が無いときは、行の下に弱い文字で「BGM が無いので、今回の書き出しには効きません」と添える。
- 「BGM を入れる」への導線を残すなら、チェックとは別の文字ボタンにする（押した結果が予想と違う、を無くす）。
- #254 で BGM は番組の既定の構成から入るのが普通になった。BGM が無い回は「既定の構成に BGM が無い」か「この回で外した」かのどちらかなので、
  案内の文言は「収録タブで BGM を入れられます」程度にとどめ、画面は移さない。
- **下げ幅の既定の置き場所【提案】:** 今は番組画面の「BGM ダッキング」（`bgm_duck_db`）が新しいエピソードの既定で、書き出しタブの下げ幅はその回だけの値。
  #254 の「この構成を既定にする」は音量やフェードを写すのに下げ幅は写さないので、「既定にしたのに下げ幅だけ戻る」が起きる。
  - **推奨: 「この構成を既定にする」で下げ幅も写す**（その回の `sound_settings.ducking.depthDb` → `bgm_duck_db`）。
    #254 で「既定はエピソードで作って、写す」に決めたので、下げ幅だけ別の入口に残すと規則が 2 つになる。BGM の音量と下げ幅は耳で一緒に決める値でもある。
  - **推奨: 番組画面の音量の ± と「BGM ダッキング」の欄は外し、枠の素材の選択だけ残す。**
    フェードの欄を置かない決定（#254）と同じ理由で、既定の値はエピソードで聞いて決めて写す 1 本にする。素材の選択は、まだエピソードが無い人が最初の構成を決める入口として要る。
    外した所には「音量・配置・フェード・下げ幅は、エピソードの『この構成を既定にする』で変わります」と 1 行添える。
  - ユーザー判断待ち。

## 6. 収録 ⇄ 書き出しの切り替えのちらつき

**原因【事実】**（`src/app/episode/[id]/index.tsx`、`ExportTab.tsx`）

1. タブごとに**根の要素が違う**（release/0.1.0 でも同じ【事実】）（収録は `StudioTab` が自分の `Screen` を返し、書き出しは `Screen` の中に `ExportTab`）。
   切り替えるたびに画面全体（見出しの行・「収録 / 書き出し」の切り替えも含む）が捨てられて作り直される。
2. `ExportTab` は `sound` を `null` で始め、マイクロタスクで読み込む。最初の 1 フレームは `<Loading>`（`ExportTab.tsx` の `if (!episode || !draft || !sound) return <Loading … />`）を出すので、
   「読み込み中 → 中身」と一瞬入れ替わる。
3. `ExportTab` を開くたびに、書き出し履歴の読み込み・試聴のチャンネル切り替え・ラウドネスの測定開始が走る。

**提案【提案】**

- `sound` は `episode.sound_settings` から**同期で初期化**する（`useState(() => parseSoundSettings(…))`）。`<Loading>` を出す場面を無くす。2 だけで目立つちらつきは消える見込み【仮説】。
- 見出しの行と切り替えを、両タブで共通の親に置き、タブの中身だけを入れ替える。
  #254 で収録タブの作り直しが重くなった（波形・構成の帯）ので、こちらの効果も大きくなっている【仮説】。
- 一度開いたタブは残して非表示にする（`display: 'none'`）方法もあるが、書き出しタブの試聴の正規化・チャンネル切り替えが「離れたら戻す」前提で書かれているので、
  残す場合はそれらを「表示中かどうか」で切り替えるよう直す必要がある。まず上の 2 点で様子を見る。
- 実機で確かめる（Development Build）。シミュレーターだけで完了としない。

## 7. 詳細設定の各項目の説明（ⓘ）

**現状【事実】:** ⓘ（`InfoButton`）があるのはトゥルーピークとビットレートだけ。下げ幅・アタック・リリース・声のしきい値には無い。

**提案【提案】:** 4 つとも `t.glossary` に足し、`Stepper` の `info` に渡す。書き出しにどう効くかを書く（文言は ja / en の両方）。

| 項目 | 説明の案 |
|---|---|
| 下げ幅 | 声が入っている間に BGM をどれだけ小さくするか。数字が小さい（マイナスが大きい）ほど BGM が静かになる。-10 dB でおよそ半分の大きさに聞こえる |
| アタック | 声が出てから BGM が下がりきるまでの時間。短いと話し始めがはっきりし、長いと BGM の変化が目立たない |
| リリース | 声が止まってから BGM が元の大きさに戻るまでの時間。短いと話の合間に BGM が出入りして落ち着かない。長いほどなめらか |
| 声のしきい値 | これより大きい音を「声」とみなして BGM を下げる。息や雑音で BGM が下がるなら上げ、声が小さくて下がらないなら下げる |

- 目標ラウドネスのチップ（-14 / -16 / -18 LUFS）にも、見出しと ⓘ（既存の `t.glossary.loudness`）を付けるとよい。今は見出しが無く、何の値か分からない。

## 8. 詳細設定の開閉と配置

**現状【事実】**（`ExportTab.tsx`）

- 開閉ボタン（「詳細設定 / 詳細設定を閉じる」）は**書き出しボタンの下**にある。
- 開くと、中身はボタンより**上の 2 か所**（仕上げのチェックの中、形式のチップの下）に差し込まれる。
  押した所から離れた場所が変わり、しかも書き出しボタンが押し下げられる。何が開いたのかが分かりにくい。
- 詳細の中身に見出しが無く、「音の仕上げ」と「形式」の境目が分からない。

**提案【提案】**

- 書き出しボタンは常に**画面の一番下（または固定の下部バー）**に置き、詳細の開閉で位置が動かないようにする。
- 「詳細設定」は**アコーディオンの見出し行**（行全体が押せる、右端に ⌄ / ⌃）にし、**中身は見出しの直下に開く**。
- 中身は小見出しで 2 つに分ける:
  - **音の仕上げ**: 目標ラウドネス、トゥルーピーク上限（ラウドネスが入っているときだけ）、ダッキングの 4 項目（ダッキングが入っているときだけ。§5）
  - **ファイル形式**: プリセット、カスタムの項目
- 並びの案:
  1. 試聴（今のまま）
  2. 仕上げのチェック 3 つ
  3. 形式のチップ（M4A / WAV）と見込みのサイズ
  4. ▸ 詳細設定（開くとこの下に「音の仕上げ」「ファイル形式」）
  5. 書き出して共有（ボタン）
